# D4 final three unknowns

Decision record: `sheets/decisions.tsv#dec325`. Scope: the three update-v262144 `main` functions that remained `unknown` after the D4-PAR gap recovery (`dec302`-`dec303`): `01fda8ec`, `02ee6a54` and `02eea158`. Result: all three are now `analyzed_documented`; none stays unknown. This is documentation evidence only: no name, signature, type, game purpose, N2, implementation, behaviour or binary-match claim is made, and the fix2 profile was not regenerated by this task.

## Method and sources

- Evidence: raw machine code of the update `main` image (`work/pla/pk2/main.elf`, SHA-256 `b772390207e0de689ca96adaeb15df8b1499912efa74804c3766214d76d08cf2`; text segment file offset = virtual address + 0x1000), read locally. No GhidraMCP server and no Ghidra process was used.
- Decoding: Capstone (`cstool arm64`) for the reading copy; llvm-objdump as an independent decoder. Both give the same instruction count, the same mnemonics and the same branch targets for all three ranges.
- Why the earlier attempts stopped: for `01fda8ec` the decompiler response was too large (the code itself is a single coherent function); for `02ee6a54` and `02eea158` the decompiler fails with an unresolved-varnode error while the code is valid (full prologue/epilogue, regular instruction stream). The earlier "no body / likely invalid entry" reading is superseded.
- Audit: the summaries were written after a first read and then audited by a second fresh read plus scripted checks of instruction counts, call-target counts, branch containment, offsets, immediates and addresses (all checks passed after the first-pass mis-statements were corrected).
- Publication rules: no game binaries, bytes, pseudocode or string contents are included here. The full operation summaries are kept in the git-ignored `work/d4/final-three/summaries.md`.

### 01fda8ec

- One entry, one return (`0x01fe618c`), no indirect branch, all direct branches inside the range; the next function starts at `0x01fe65d0`. 540 `nop` (patched thread-local relocation sequences). The older 3,652-byte export ends at `0x01fdb730`, right after the first call to PLT stub `0x032a2520`.
- Inputs: x0 plus x1-x7 and 111 stack slots, each dereferenced as a pointer to a 16-byte value. Writes a table of 130 read-only-data pointers, 117 sixteen-byte copies and code-address constants into the object in x0 (offsets `+0x0` to `+0xc10`).
- Structure (address order): object initialisation; 125 repeated blocks that call `strlen` on a stored pointer and build a short or heap-backed string record in a 131-entry stack array of 0x30-byte records (5 further records from fixed-size literals, 1 from a literal at the start); a loop that inserts the 131 records into a bucketed table at the object (hash-like value from callee `0x007e8ed4`, chain compare with `memcmp`, 0x40-byte node allocation, load-factor test and rehash call `0x007e9ae4`); a 32-iteration loop that looks up and releases entries (`0x007e8c90`, `0x007f2aec`); 130 `strlen` + `0x007f2c60` calls whose results are OR-combined into a flag byte at object `+0x58`; a loop that releases heap-backed records; epilogue.
- Calls: `strlen` 255, `memcpy` 125, `memcmp` 2, libc++ `__throw_length_error` 125 (cold stubs `0x01fe6190`-`0x01fe65cc`), libc++ `basic_string` copy constructor 1, `__cxa_thread_atexit` 3, `0x007f2c60` 130, `0x007e8ed4`, `0x007e9ae4`, `0x007cca50`, `0x007e8c90`, `0x007f2aec` 1 each, `0x02acc824` 3. ### 02ee6a54

- Valid function: one entry, one return (`0x02ee705c`), all direct branches inside the range. Mostly 128-bit float vector code (149 `fmul`, 54 `fadd`, 32 `fsub`, 30 reciprocal-square-root and 21 reciprocal steps, lane compares and selects).
- Inputs: x0-x5 (x1 unused); a record reached through a self-relative offset at `x0+0x40` selects the path by the byte at record `+0x18` (values 0, 1, 2, 4; anything else goes to a generic path). Paths: vertex-block loop (4 vectors per iteration), point/segment-style vector arithmetic, a two-call variant of `0x000d42c0`, a transform path that normalises up to 0x40 (more via helper `0x031bd1d4`) 16-byte vectors, and an arena path that allocates from a thread-local bump allocator (`tpidr+0x38d490`), transforms 12-byte points and calls `0x000d0a00` between two marker calls (`0x031d5af0`, `0x031d5b34`).
- Result delivery: a 0xb0-byte stack block is filled and passed to an indirect call through vtable slot +0x28 (`0x02ee703c`); target unresolved (the stack object's vtable pointer is the data address `0x041b0ba0`, unrelocated in the ELF).
- Calls: `0x000d42c0` x2, `0x000d0a00` x2, `0x031d5af0` x2, `0x031d5b34` x2, `0x0323d16c` x6, `0x031cf244`, `0x031cedf0`, `0x031bd1d4`, `0x031ce670`, `0x031bd0a8` (19 direct), 1 indirect.

### 02eea158

- The symbol is a 5-instruction entry stub (re-arranges x0-x3 from `[x0+0x50]`, x2, x3, x5 and branches to `0x030049a8`). The recorded 5,816-byte body omits 312 instructions in 9 gaps; these are the targets of the function's own nine jump-table dispatches (`br` at `0x03004ca0`, `0x03004d5c`, `0x03004db0`, `0x03004df8`, `0x03004f24`, `0x03004f68`, `0x03004fac`, `0x03005028`, `0x03005160`). All table targets (rodata tables at `0x039a4734`, `0x039a473c`, `0x039a475a`, `0x039a475e`, `0x039a4762`, `0x039a4766`, `0x039a476e`, `0x039a4776`, `0x039a477e`) and all direct branches fall inside `0x030049a8`-`0x0300652b`; the next function starts at `0x0300652c`. The documented extent is therefore the stub plus that contiguous range (1,766 instructions).
- Structure: an early return when a flag byte at `x0+0x15df` is zero; a loop over a stack of node pointers (128-byte nodes, six 16-byte rows each, 4-bit mask from integer min/max compares, child ordering through lookup tables, prefetch and push); leaf entries are processed per index with vector arithmetic and per-kind paths, a call to `0x000d42c0` (two sites) or `0x000d0a00` (marker calls `0x031d5af0`/`0x031d5b34`), and an indirect call through vtable slot +0x28 of the object in x3 (`0x0300511c`); it also writes the minimum of a float pair back into the caller's structure (`x3+0x10`).
- Calls: `0x031c9fc0`, `0x000d42c0` x2, `0x031d5af0`, `0x000d0a00`, `0x031d5b34`, `0x0323d16c` x2 (8 direct sites), 1 indirect, 9 jump-table dispatches. Table contents beyond the jump offsets were not decoded.
