## Scope rule and result

The target is the **base game with update v262144 applied**. The update is a patch, not a standalone program. Base-only facts are not effective-overlay denominators. “Included” below means included within the stated bounded census layer, not semantically understood, behaviorally verified, or runtime-used. “Excluded” requires affirmative boundary evidence; no candidate dimension below is affirmatively excluded. “Blocked” means the needed evidence is unavailable or gated; it is not an exclusion. Counts of listed candidate dimensions are an audit checklist, **not a complete universe**.

The present discovery boundary remains open: no documented exhaustive discovery method, enumeration rule, or stopping condition proves that all package classes, data families, systems, runtime services, or valid functions have been found. Therefore the matrix does not assert a complete universe and does not manufacture missing denominators.

## Dimension count and decision summary

This matrix contains **14 candidate dimensions**. **12/14 have direct evidence for at least one bounded layer** (package rows; Program/ExeFS; module roles; outer RomFS; nested archives; base/delta scripts; candidate asset-format families; selected non-RomFS metadata; static dependency candidates; bounded function inventories and state partitions; heuristic subsystem labels). **2/14 lack a qualifying positive enumeration for the requested dimension**: the discovery boundary itself and actual runtime file access/reachability. Runtime provider resolution is separately **blocked/unknown** despite static candidate evidence; complete effective script/asset/nested-member universes and complete subsystem/function universes also remain unknown. Across the matrix, **0 dimensions are affirmatively excluded**, **12 have partial direct evidence**, and **2 have no qualifying positive enumeration**. These are overlapping evidence/status views: partial evidence does not close a dimension, and no “zero coverage” or absence claim follows from unknown.

The arithmetic above uses dimension rows, not source artifacts or game items. It does not define a complete game-wide denominator. In particular, outer RomFS totals, nested archive members, script rows, asset-format counts, module functions, and runtime observations have different units and must not be summed.
