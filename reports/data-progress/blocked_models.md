# Blocked field models and skeleton-less models (Brief 19)

Measured on Pokémon Legends: Arceus v262144 with the user's local extract
(`work/pla/pk2/romfs_patched`); game data stays out of git. The typed indexes
([field models](../../data/field_model_export_index.tsv),
[Pokémon packs](../../data/pokemon_model_export_index.tsv)) were regenerated by
the exporters themselves; the raw census table lives in `work/census/`
(git-ignored).

## What changed

- `TrMbf::indices` is now `Vec<u32>`: the raw index bytes of
  `objects_area00_house01_a/b` (134 353 vertices) and
  `objects_area01_changeflower01_a` (89 585) are UINT32; a `u16` source is
  widened losslessly. The shape field 2 mapping (1 = UINT16, 2 = UINT32) was
  verified against those raw byte ranges and against u16 samples where the u32
  reading is out of range.
- `TrShapeLayout` (new): parses the `.trmsh` FlatBuffer shape declarations
  (stride, index width, attributes with layers, contiguous coverage). The
  FlatBuffer shape is the authoritative declaration when the bounded legacy
  section is malformed or absent. Format code 54 gets a 16-byte width — forced
  by contiguous coverage in every shape that declares it; its **semantics stay
  unknown** (kept opaque, never exported as a semantic attribute).
- `TrMbf::parse_with_shape_layout` (new): one `.trmbf` payload per shape,
  container buffers (one FlatBuffer buffer per shape) or single-buffer files,
  container precedence (a container can coincidentally mirror the single-buffer
  header: `objects_area01_kingtree01`). Shapes are parsed lazily so an
  unsupported later shape does not hide a usable earlier one (pm0628 shape 3).
- Field exporter (`export_field_gltf_batch`): legacy layout first, shape
  declaration as fallback; a mesh without the demonstrated unique ID 7/8 pair is
  exported as a **static mesh**, and so is a mesh whose skeleton cannot be built
  (reason recorded in the index). 51+ models whose skeletons still work keep
  their skin; the transition table has **zero** `ok → blocked` rows.
- Pokémon assembler (`pokemon_model::assemble_pack`): falls back to the shape
  declaration when the strict skin parser rejects a shape (layered declarations
  in pm0628). `pokemon_batch_export` already had the static fallback.
- `MAX_SHAPE_STRIDE = 128` applies only to declared shapes (observed 68);
  the legacy heuristic paths keep the previous 64-byte bound.
- UV0 now uses the declared ID 6 / format 48 offset (lowest layer) instead of
  the hardcoded 28; every previously exportable model still exports (0
  regressions), and models whose UV0 sits elsewhere become exportable.

## Verification

- Unit tests: `cargo test -p pla` = 713 tests passed (622 lib + 91
  integration; 2 ignored), all green. New synthetic tests cover the shape
  parser (layers, UINT32, format 54 width, gaps/duplicates), single-buffer and
  container payloads, out-of-range indices and the unique-skin-pair predicate;
  no game bytes are used.
- Exporter regression guard (`crates/pla/tests/model_export_guard.rs`):
  `pm0025_00_00` and `pm0026_00_00` assemble, keep LOD0 meshes and clips, and
  write a skinned glTF with skin + animation blocks (tested with the real packs
  via `PLA_FIXTURES=<pokemon dir>`; skips when the fixture is absent).
- Whole-corpus structural verification (new non-windowed example
  `verify_field_gltf_json`): 834/834 field glTFs and 1046/1046 Pokémon glTFs
  parse, their buffers match the `.bin` files, accessors stay inside their
  buffers, positions are finite and bounded, UINT32 indices are complete
  triangles inside the vertex range, and textures/skin/animation references
  resolve — **0 errors**. Rendering was not re-run: no windowed process was
  started (operating rules), so the visual result is for the maintainer to see.

## Assumed / unknown

- Static is the honest fallback for meshes without skin channels, but "the game
  never deforms them" is PROBABLE, not proven by a render.
- When a model declares several shapes (flag models: 2, kingtree: 3, some rooms:
  39) the exporter writes the first successfully parsed shape; whether the game
  uses the other shapes (LODs? variants?) is **unknown**.
- The 8 skeleton-unavailable models are exported static where the old code also
  exported them static silently; the index now names the reason.
- pm0570's skeleton/animation is exported and structurally valid, not visually
  checked. pm0628 stays static until the bind/rest disagreement is resolved.
- Format 54 semantics, and the meaning of the ID 5 attribute in the 40/52-byte
  layouts, remain unknown.

## Reproduce

```bash
cargo run -p pla --example blocked_models_census -- field <romfs> work/census/field_diagnosis.tsv
cargo run -p pla --example export_field_gltf_batch -- <romfs> <cache>/gltf_field data/field_model_export_index.tsv
cargo run -p pla --example pokemon_batch_export -- <romfs>/bin/archive/pokemon <cache>/pokemon_batch data/pokemon_model_export_index.tsv --force
cargo run -p pla --example verify_field_gltf_json -- <cache>/gltf_field work/census/gltf_verify.tsv
PLA_FIXTURES=<romfs>/bin/archive/pokemon cargo test -p pla --test model_export_guard
```
