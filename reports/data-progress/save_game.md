# Player save (own port format)

Module: `crates/pla/src/game/save_game.rs`. This is the port's own save, not the original game's format (`crates/pla/src/save.rs` only emulates the original host save API for scripts and is untouched).

## Format
Strict line-based text, no new dependencies (`serde` is not a dependency; only `serde_json`). File `save.plasave`:

```
PLASAVE 8
CHECKSUM <fnv1a64 hex of every byte after this line>
zone=ha_area01          pos=x,y,z   yaw=..   time_minutes=..   money=..
defeated=..  caught_count=..  rng_seed=..  play_seconds=..
seen=1,25,722  caught=722   bag=item:qty,...
picked=<hex ids> (v7)   defeated_trainers=giratina01,noble:nsi_ex_01 (v8)
member=species|form|level|hp|status|e0:e1:e2:e3:e4:e5|move:pp,move:pp|nickname-hex
box=species|form|level|hp|status|e0:e1:e2:e3:e4:e5|move:pp,move:pp|nickname-hex
END
```
Unknown keys, duplicate keys, bad numbers, missing required fields, non-finite floats, more than 6 party members / 4 moves / 960 box slots are rejected. `member` and `box` are the only keys allowed to repeat. `END` is inside the checksum so truncation at any length fails. Sets are sorted, so output is deterministic. Nicknames are hex-encoded (`-` none, `~` empty).

## What is saved
Zone id, player position and yaw, game-clock minute of day (`time_minutes`, 0..1439, format v6), party (<= 6: dex id, form, level, current HP, status, per-move PP, effort level, optional nickname, cumulative experience (format v5, `-` = unknown)), box (`box_pokemon`, <= [`MAX_BOX`] = 960 stored Pokemon, same record as a party member), bag (item id -> qty), money, seen/caught dex sets, defeated and caught counters, RNG seed, play time (`play_seconds`, u64 whole seconds, format v4).

## API
- `PlayerSave::{encode, decode, validate}`; `SaveError` (friendly `Display`, never panics).
- `SaveFile::{in_dir, from_env, read, write, load_with_fallback, backup_path}`; write is temp file + fsync + rename, previous save copied to `save.plasave.bak` first; a damaged main file falls back to `.bak`.
- Location: `PLA_SAVE_DIR`, else `$XDG_DATA_HOME/pla-port`, else `~/.local/share/pla-port`.
- `SaveGame` Bevy resource: `save(PlayerSave) -> bool`, `load() -> Option<PlayerSave>`, `message` (text for the UI).
- Engine conversions: `PartyMember::from_combatant(&Combatant)`, `PartyMember::to_combatant(species, moves, nature_percent)` (stats recomputed from level + effort; HP, PP, status restored), `SavedStatus <-> MajorStatus`, `PlayerSave::bag_from_engine(&ItemBag, ids)`, `PlayerSave::bag_to_engine(&ItemTable)`.
- Versioning: `CURRENT_VERSION = 8`; `migrate()` chains steps. v1 (members without form/effort) -> v2, v2 (no box) -> v3, v3 (no play time) -> v4 v4 (8-field members/box entries) -> v5 and v5 (`time_slot`) -> v6 are implemented and tested. v2->v3 and v3->v4 are documented no-ops: the parser defaults a missing `box` list to empty and a missing `play_seconds` to 0. v4->v5 appends `-` (unknown experience, read as the saved level's threshold) to every member and box line ([progression wiring report](progression_wired.md)). v5->v6 turns the coarse `time_slot` 0..3 into `time_minutes`, the centre minute of that slot (03:00/09:00/15:00/21:00; the slot hours are SUPUESTO), or the default start time if the line is missing ([clock report](clock_weather.md)). v6->v7 (collected field-item ids, `picked`) and v7->v8 (`defeated_trainers`) are documented no-ops: the parser defaults a missing key to the empty set. The next bump is v9.

## Wiring (done in `crates/pla/src/game/save_wire.rs`)
- `PlayerProgress` resource: party (<= 6), box list (persisted as `box_pokemon`), bag map, money, seen/caught sets, defeated/caught counters, rng seed, time slot. Seeded with the demo party (Pikachu, Bidoof, Starly) and starter bag, or from the save.
- Box operations (pure, no Bevy): `PlayerProgress::deposit(PartyMember)`, `withdraw(box_index)`, `swap(box_index, party_index)`, each returning `Result<_, BoxError>` (`BoxFull`, `PartyFull`, `BadBoxSlot`, `BadPartySlot`). No UI uses them yet; they exist for the box screen (task 32) and are unit tested.
- Each battle: `install_party` rebuilds the player side from the saved members (HP, PP, status restored; fainted stay fainted; first living member leads; if all are fainted the party is restored, a placeholder for a village return); `engine_bag` and the rng seed are installed. Every frame `snapshot` + `apply_sync` mirror party and bag back; when the session disappears `apply_outcome` updates seen (on encounter), caught/caught_count, defeated (win), then autosaves. A catch goes to the party while it has room, otherwise it is `deposit`ed into the box; if the party AND the box are full the catch is still counted (caught set + `caught_count`) but not stored.
- Start-up (`load_startup`): zone, position (x/z), player yaw, time slot, play time, party, bag, sets from `SaveGame::load` (message shown as a HUD toast). Explicit `--area`, `--player-pos`, `--time-slot` win over the save. Height is recomputed from terrain.
- Play time (`crates/pla/src/game/play_time.rs`): `PlayTime` resource counts real seconds via a pure `accumulate(dt)` (sub-second remainder kept, NaN/negative ignored, saturating). The `counts_play_time` run condition ticks it only in `GameState::World`/`Battle` and outside pause; every save (`do_save`) stamps `play_seconds` from it, and `PlayTimePlugin::install` seeds it from the loaded save.
- Victory money: `apply_outcome` pays `victory_reward(wild_level)` = `50 + 10 x level` (ASSUMED, see below) once per won battle, saturating in `PlayerProgress::add_money`. `BattleOutcome` now carries `wild_level`. Catching and running pay nothing.
- Rest (`MenuOption::Rest` -> `MenuAction::Rest` -> `RestRequested` -> `rest_action`): `rest_party` rebuilds each member with the engine tables and restores HP to max, clears status and refills PP to each move's max, keeping form and nickname; unknown species are skipped and reported. Refused during a battle or without the battle tables; the result is a HUD toast. No clock is advanced (Brief 9 owns the clock; the original's rest durations are not decoded).
- Pause menu: rows now Resume, InvertX, InvertY, Volume, SafeSpawn, Save, Rest, Quit; the panel shows `Money: N · Play time: H:MM:SS` (`menu_info_text`), read from `PlayerProgress`/`PlayTime` with 0 fallbacks.
- F5 saves in the world (refused during a battle); autosave after each battle and when `ActiveZoneInfo` changes (the viewer has no runtime zone change yet, so that path is untested live).
- CLI: `--new-game` (ignore save), `--save-dir <path>` (sets `PLA_SAVE_DIR`), `--save-selftest` (evidence log).
- Tests: 23 unit tests in `save_game.rs` (including the v4->v5 experience and v5->v6 clock migrations) and 21 in `save_wire.rs` (temp dirs only); 8 of the `save_wire` ones use the real battle engine and skip when the data tables are absent; 5 in `play_time.rs` (including a headless Bevy test of the tick + run condition) and 9 in `pause_menu.rs`. `cargo test -p pla -- save_ pause play_time` -> 68 passed, 0 failed (2026-10-13; the filter also picks up unrelated names containing `save_`/`pause`).
- Play-time evidence: migration of a literal v3 body (box kept, `play_seconds` 0, experience unknown, re-save now writes `PLASAVE 5`), a u64::MAX round trip, the stamping path (save 4242 -> `load_startup` returns 4242), and a headless Bevy test where 250 ms frames count in World/Battle and never while paused or in `BattleEnded`.
- Money evidence: `victory_reward` formula, prize paid once per win and not on run/catch, saturation at `u32::MAX`, and a real-engine snapshot test where fainting the wild pays `victory_reward(wild_level)`.
- Rest evidence: full HP/PP/status restore keeping nickname (real engine), idempotence, unknown-species skip with report text, request consumption and toast text with and without the battle tables (headless).
- Box evidence: round trip with a non-empty box, v2->v3 migration of a literal v2 body (empty box), the `MAX_BOX` boundary refused on write and on read, a malformed `box` member rejected, a full party routing a catch to the box and reloading it from the file, `deposit`/`withdraw`/`swap` (including limits) and a full-box catch counted but not stored. The full-party catch test also runs the real `battle_engine` and reloads the file.
- Evidence: one offscreen `--script` run with a temp save dir (`--new-game --save-selftest`): party before battle `#25 hp=78; #399 hp=92; #396 hp=64`, after `#25 hp=67; ...`, reloaded from the file identical. The reload was done in-process with a fresh file handle, not a second process. (From the pre-v4 run; kept as historical evidence.)

## Defeated trainers (format v8)
`defeated_trainers=` is a sorted comma list of trainer ids (`data/trainer_index.tsv` ids such as `giratina01`, or `noble:<setting>`); an id may not be empty or contain whitespace, control characters, `,` or `=` (refused on read and write). A v1-v7 file loads with an empty set and re-saves as v8. `PlayerProgress.defeated_trainers` is the runtime copy (the old session-only `DefeatedTrainers` resource is gone); the legacy counter `defeated` is kept. `apply_outcome` inserts the id on the first win and pays the prize only then (a rematch through `--trainer` pays nothing); the battle-end autosave writes it. Esc > Save / Load, F5 and the automation `save` / `load` all go through `to_save` / `from_save`, so they carry it. Tests: `defeated_trainers_round_trip_and_v7_migration` (save_game.rs), `defeated_trainer_survives_save_and_load` (trainer_encounter.rs: win, autosave, in-process Load and a fresh app, marker grey, V starts nothing, money unchanged), and the rematch case in save_wire.rs.

## Still not done

The box is persisted but has no screen (task 32) and no reordering/sorting; the party is auto-filled from the box only through the pure `withdraw`/`swap` helpers, which no system calls yet. Money is only paid for wins with the provisional formula; the original's reward tables are not decoded.

## Verified / Assumed / Unknown
- **Verified** (by the tests above, `cargo test -p pla -- save_ pause play_time`, 68 passed): the box encodes/decodes and survives a file round trip; v2, v3, v4 and v5 saves migrate to v6 (empty box / play time 0 / experience unknown / slot-centre minute of day); the `MAX_BOX` limit is enforced on write and on read; a catch with a full party is deposited in the box; `deposit`/`withdraw`/`swap` respect `MAX_BOX`/`MAX_PARTY` and slot bounds; `play_seconds` round-trips including u64::MAX; play time counts only in World/Battle outside pause; a win pays the provisional prize exactly once and saturates at `u32::MAX`; rest restores HP/PP/status without touching form or nickname and is refused without the tables.
- **Assumed**: the victory formula `50 + 10 x level` (the original's money amounts are not decoded); treating "Rest" as a full heal that keeps the party composition and advances the clock to the next slot (the original offers morning/midday/evening/night/little while at tents — `n2-base-camps-and-travel.md` §2.1 — and its durations are UNKNOWN; Brief 9 chose "next slot"); sending a full-party catch to the box; the 960-slot ceiling (30 boxes x 32).
- **Unknown**: the original's money amounts and rest durations/health rules, how the original counts play time, the real game's box capacity and the behaviour when the party **and** the box are both full. Nothing here was checked in a windowed session (no viewer run: money/rest/toast are unit-tested only; the human must eyeball the menu text and the rest flow).
