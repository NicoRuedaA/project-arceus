# PML tables and proven mechanics

`pla::pml` loads the five typed TSVs in `data/` into Rust records. The reader skips leading `#` metadata, uses the first remaining line as the typed header, and validates every row's field count and parsed values. Counts are 1,276 personal/form rows, 600 growth thresholds, 146 evolution rows, 851 move rows, and 26,160 learnset rows.

The N2 evidence supports the observed `PokemonParam` offsets, level clamp to 100, raw IV slot order, Ganba K values `[0, 2, 3, 4, 7, 8, 9, 14, 15, 16, 25]`, and the documented HP expression (including the supplied Shedinja-predicate override). The decoded gender codes 0/127/254/255 are represented as all-male/equal/all-female/genderless; other values remain `Unknown(raw)`. The table's `is_active` flag is retained as decoded, but its source uses `base_hp > 0` as a proxy, not a proven native presence predicate. Growth curves provide cumulative experience by group and levels 1–100; requests above 100 clamp to the cap. PLA evolution methods 48–54 are named but only retain their raw trigger arguments; this module does not evaluate evolution conditions.

Non-HP calculation is deliberately partial: the native `Intermediate` term, full nature matrix and exact nature mapping/rounding are not proven by the cited reports. The calculation requires those values as explicit inputs and otherwise returns `None`. The experience-to-level comparison boundary is also unknown; only level-to-threshold lookup is implemented. Learnset level/mastery field-width disagreement (community schema u16 versus decoded TSV u8) and move-ID coverage/uniqueness (851 rows, duplicate ID 1, missing ID 0) remain unresolved. Names, display labels, `base_stat_total`, and condition details are decoder output, not native semantic proof.
